The core loop

One moment, five deliberate steps.

No mandatory account. No instant paywall. No generation while someone is still typing. The user decides when writing begins and what happens to the result.

Writing routes

Two lanes. One product promise.

The interface talks about the kind of help a person wants. Models, providers, tokens, and routing mechanics stay behind a single MessageWritingService boundary.

Everyday route

Private draft

Designed for ordinary personal messages where Apple’s on-device model is available.

  • Message context remains on device during generation.
  • Foundation Models uses typed output rather than provider-shaped UI.
  • Relationship memory can enrich the prompt locally.
  • Availability and timeout failures are translated into honest product language.
Higher-care route

Take more care

Designed for harder moments and explicit careful rewrites through the ProsePal gateway.

  • The app sends a versioned, length-capped request—not an open-ended chat transcript.
  • Authentication, provider choice, quality checks, and usage policy stay server-side.
  • Provider and model names never appear in the app.
  • User-safe errors preserve retry and fallback behavior without leaking internals.

Fallback is selective rather than universal. Cancellation and content refusals keep their own semantics, and each transport owns its timeout.

ProsePal gateway

A narrow server boundary, not a second app.

The gateway accepts a stable card-writing contract, validates it, calls a configured provider, checks the result, and returns provider-neutral messages and errors.

AUTH

JWT verification

Authenticated requests are verified through Supabase Auth. Anonymous development access fails closed unless its separate secret is configured and matches.

INPUT

Bounded contracts

Recipient, include, avoid, context, client metadata, lanes, and contract versions are sanitized and length-capped before provider work.

ROUTE

Server-side provider choice

Provider URL, key, model, fallback models, sampling, token limits, and JSON behavior remain outside the client.

QUALITY

Output checks

Responses must be structured, distinct, non-empty, appropriately specific, and free of generic filler or provider/internal language.

PRIVACY

Metadata-only logs

Operational logs carry lanes, versions, latency, failure buckets, and redacted identity—not prompts, names, tokens, or generated drafts.

FAILURE

Safe degradation

Provider timeouts, malformed output, quality failure, auth failure, configuration failure, and usage limits map to stable user-safe errors.

The product in use

From a person to a kept message.

The same writing object moves through setup, result, and deliberate local storage. It does not become a chat transcript or an automatic content history.

Trust foundations

The quiet systems doing the serious work.

Identity, payments, local memory, and diagnostics are separated so each boundary can fail honestly without corrupting another.

Identity and session continuity

Sign in with Apple exchanges identity through Supabase Auth. The resulting session is stored in the device-bound Keychain. Expired access tokens refresh through a single shared operation, persist rotation before use, preserve identity during transient network failure, and clear only on terminal rejection.

StoreKit and entitlement integrity

Apple remains the purchase authority. The app loads configured products, supports purchase and restore without mandatory app sign-in, listens for transaction updates from launch, ignores unverified transactions, and finishes verified transactions only after entitlement convergence succeeds.

Local data and privacy

Truth Beads, Voice Cards, and saved drafts live in a versioned SwiftData vault. The store is excluded from backup, supports migration, can fall back ephemerally instead of crashing, exports user-readable JSON, and is erased during local-data or account deletion.

Failure is part of the product

No fake controls. No invented certainty.

The app names what happened and preserves the user’s work. Provider internals, quota fiction, and decorative retry states do not belong on the screen.

OFFLINE

The note stays local

“Try again” performs a real retry. Repeated taps and late results cannot replace newer work.

TIMEOUT

The lane is named honestly

On-device and gateway timeouts have separate product-neutral explanations and cancellation behavior.

LIMIT

The server supplies the policy

The UI avoids invented weekly limits, reset dates, meters, or “unlimited” promises.

REFUSAL

Safe, calm presentation

Model and gateway refusals become understandable app language without exposing the provider.

SAVE

Success follows persistence

Memory edits and deletes show success only after the local save succeeds; failures roll back.

CONFIG

Missing means unavailable

Unconfigured auth, gateway, subscriptions, or local model capability produce explicit readiness states—not empty buttons.

V1 product boundary

Focused by what it refuses to become.

  • No manuscript, scene, project, or document-manager workflow
  • No mandatory account before first value
  • No forced paywall immediately after welcome
  • No provider or model names in the interface
  • No client-side provider API keys or provider SDKs
  • No automatic visible generation history
  • No silent relationship-memory inference
  • No app-owned therapy or mental-health inference system
  • No analytics or crash toggles for systems that do not exist
  • No fake settings rows, retry controls, or quota claims
